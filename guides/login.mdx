## Overview

Authentication uses Firebase Auth on the client. After sign-in, the Firebase ID token is sent as `Authorization: Bearer <idToken>` on every API call — that token is all Distrify needs to identify the user and scope their requests.

## Step 1 — Sign in with Firebase

The web app uses the Firebase JS SDK directly. Three methods are supported:

| Method           | Firebase call                                                            |
| ---------------- | ------------------------------------------------------------------------ |
| Email + password | `signInWithEmailAndPassword(auth, email, password)`                      |
| Google           | `signInWithPopup(auth, new GoogleAuthProvider())`                        |
| Phone + OTP      | `signInWithPhoneNumber(auth, phone, recaptcha)` → `result.confirm(code)` |

When any of those resolve, Firebase persists the session and `onAuthStateChanged` fires with the `User`. From that user you can call `user.getIdToken()` to retrieve the JWT.

<Note>
  The token expires every hour. The Firebase SDK refreshes it automatically; if
  you call the API from a non-JS client, refresh the token with the [Firebase
  REST refresh
  endpoint](https://firebase.google.com/docs/reference/rest/auth#section-refresh-token).
</Note>

## Step 2 — Discover the user's organizations

Once Firebase has authenticated, ask the platform which organizations the user belongs to:

<Card title="GET /api/users/v1/auth/organizations" icon="building" href="/api-reference/authentication/list-organizations">
  Returns `{ authId, organizations[], needsSelection }`.
</Card>

### Response shape

```json
{
  "authId": "firebase-uid-abc123",
  "organizations": [
    {
      "organizationId": "0190a4f7-7d39-7c2c-9b1a-9c8a2e7d3f01",
      "organizationName": "Acme Distributors",
      "role": "STAFF",
      "isDefault": true,
      "userId": "0190a4f8-..."
    },
    {
      "organizationId": "0190b121-...",
      "organizationName": "Beta Wholesale",
      "role": "STAFF",
      "isDefault": false,
      "userId": "0190b122-..."
    }
  ],
  "needsSelection": true
}
```

The `needsSelection` flag tells the frontend whether to short-circuit or prompt the user.

## Step 3 — Branch on `needsSelection`

There are three cases the frontend has to handle, all of them driven by the response above.

<Tabs>
  <Tab title="Single organization">
    `needsSelection` is `false` and the array has exactly one entry. The user's scope is unambiguous — go straight to step 4.
  </Tab>
  <Tab title="Multiple organizations">
    `needsSelection` is `true`. The user belongs to more than one organization and has not picked a default yet. Show an organization picker UI (see `OrgPickerDialog.tsx` in jadix). When the user picks one, call:

    <Card title="PUT /api/users/v1/auth/default-organization" icon="check" href="/api-reference/authentication/set-default-organization">
      Body: `{ "organizationId": "..." }`. Marks that org as the default; subsequent calls are scoped to it.
    </Card>

    After a `204`, proceed to step 4. The choice is persisted, so the next time the user signs in, `needsSelection` will be `false`.

  </Tab>
  <Tab title="No organizations">
    The call returns a 401 (the firebase user has no record in Distrify yet). The frontend should open the **organization setup dialog** so the user creates an organization. See `OrganizationSetupDialog.tsx`.
  </Tab>
</Tabs>

## Step 4 — Bootstrap the session

With the organization scope settled, fetch the three pieces of context the app needs:

  </Card>
  <Card title="Staff profile" href="/api-reference/staff/profile">
    [`GET /api/organizations/v1/staff/profile`](/api-reference/staff/profile) —

## Putting it all together

```ts
import { onAuthStateChanged, signInWithEmailAndPassword } from "firebase/auth";
import { auth } from "@/lib/firebase";
import { api } from "@/lib/api";

await signInWithEmailAndPassword(auth, email, password);

onAuthStateChanged(auth, async (user) => {
  if (!user) return;

  const { organizations, needsSelection } = await api.getAuthOrganizations();

  if (needsSelection) {
    const chosen = await promptUserToPickOrg(organizations);
    await api.setDefaultOrganization(chosen.organizationId);
  }

  const [organization, staff] = await Promise.all([
    api.getOrganizationProfile(),
    api.getStaffProfile(),
  ]);
  const permissions = await api.getStaffPermissions(staff.id);
});
```

## Mobile-only: biometric login

On the mobile app the Login screen offers a Face ID / Fingerprint shortcut **after** the first successful sign-in. The flow is entirely client-side — Distrify has no biometric endpoint:

1. After the first successful Firebase sign-in, prompt the user to enable biometric login.
2. On opt-in, persist Firebase's **refresh token** in the device secure store (Keychain on iOS, Keystore on Android). Never store the password.
3. On subsequent launches, gate the secure-store read on a Face ID / Fingerprint check. If it passes, hand the refresh token back to the Firebase SDK to mint a fresh ID token, then continue from step 2 of this guide.
4. If biometric hardware is not available, hide the button entirely.

Biometric can be disabled from the in-app settings; that just wipes the refresh token from the secure store.

## Forgot password

The "¿Olvidaste tu contraseña?" link is also pure Firebase — Distrify does not own the reset flow. Use the standard SDK call:

```ts
import { sendPasswordResetEmail } from "firebase/auth";

await sendPasswordResetEmail(auth, email, {
  url: "https://app.distrify.us/auth/action",
  handleCodeInApp: false,
});
```

Firebase sends the user an email with a reset link; once they set a new password they're redirected back to the login screen and complete the flow from step 1.

## Switching organizations later

If the user wants to change the active organization without signing out, call [`PUT /api/users/v1/auth/default-organization`](/api-reference/authentication/set-default-organization) with the new `organizationId` and re-run step 4. There is no header or cookie to keep in sync on the client.
